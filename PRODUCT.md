# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated by the user: C++20/CMake simulation core plus a dependency-free browser replay dashboard. This preserves a low-friction local build and makes the actual run data inspectable without a frontend toolchain.

## Users

Primary users are the project author and technical reviewers evaluating a simulated flight-control experiment. They need to run a named scenario, inspect the recorded response, understand what is modeled, and distinguish evidence from illustrative or unmeasured claims.

## Product Purpose

Flight_Dynamics is a civilian, synthetic-trainer flight-control laboratory. It turns a reproducible C++ simulation run into telemetry, metrics, plots, and an interactive replay so engineering choices can be examined rather than merely asserted.

## Positioning

The product pairs the execution path and the visual evidence path: a dashboard only replays data generated by the included simulation and identifies its model and limitations at the point of use.

## Operating Context

The workflow is local and offline: configure with CMake, run a fixed-step scenario, inspect the CSV/JSON/SVG artifacts, then serve the repository locally to use the replay dashboard.

## Capabilities and Constraints

- Initial dynamics are an explicitly synthetic, reduced-order trainer model; no certification, real aircraft validation, real-time, hardware-in-the-loop, or JSBSim claim is permitted.
- The simulator must remain deterministic for an identical seed and configuration on one toolchain.
- JSBSim is an optional build backend and a pinned C172R open-loop trim reference; controller integration remains a future milestone. Its public API, model assets, licenses, and unit conversions must stay explicit and verified.
- The dashboard has no external runtime dependency and must label generated replay data accurately.

## Brand Commitments

Name: Flight_Dynamics / FlightLab. Voice: precise, candid, engineering-led. The user asked for a notably stronger, more polished result than a generic scaffold.

## Evidence on Hand

- A public MIT repository at `sdg5-hub/Flight_Dynamics` with its original README and LICENSE.
- Locally generated telemetry will be the only default replay source. No flight, certification, customer, or benchmark evidence is on hand.

## Product Principles

1. Show the evidence path before interpreting it.
2. Make model assumptions visible at the interface, not hidden in a disclaimer.
3. Favor deterministic, inspectable systems over theatrical simulation.
4. Separate a useful educational model from a claim of aircraft fidelity.
5. Make technical review easy at a glance and deep on demand.

## Accessibility & Inclusion

The dashboard must support keyboard-operable replay controls, clear focus treatment, responsive layouts, sufficient non-color status cues, and a reduced-motion preference.
