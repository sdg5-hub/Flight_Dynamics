# Flight_Dynamics / FlightLab

FlightLab is a C++20 flight-control experiment lab: it runs deterministic scenarios, records versioned telemetry, calculates transparent metrics, renders a plot, and replays the generated data in a local browser dashboard.

It has two deliberately separate paths:

- `synthetic` — a reduced-order civilian-trainer model with FlightLab’s cascaded PID controller. It is an educational control-software experiment, **not** validated aircraft dynamics.
- `jsbsim` — a pinned JSBSim v1.3.3 C172R open-loop trim reference. It uses an actual 6-DOF engine, but FlightLab’s controller is not connected to it yet.

No real-flight, certification, real-time, hardware-in-the-loop, or aircraft-fidelity claim is made.

## Quick start

Clone with the pinned model dependency, then build and test:

```sh
git clone --recurse-submodules https://github.com/sdg5-hub/Flight_Dynamics.git
cd Flight_Dynamics
cmake --preset default
cmake --build --preset default
ctest --preset default
```

Run the controller scenario and generate evidence:

```sh
./build/default/flightlab_run --backend synthetic --output results/nominal.csv
python3 tools/plot_telemetry.py results/nominal.csv results/nominal.svg
python3 tools/check_acceptance.py configs/acceptance.json results/nominal.summary.json
```

Run the independently modeled JSBSim open-loop reference:

```sh
./build/default/flightlab_run --backend jsbsim --output results/jsbsim-open-loop.csv
```

Replay a generated run locally:

```sh
python3 -m http.server 8080
# open http://localhost:8080/dashboard/
```

The committed sample artifacts were generated by these commands on the documented macOS toolchain. The dashboard reads CSV schema v2 and labels the selected backend/model at runtime.

## What is in the run

The nominal synthetic scenario uses a 10 ms fixed integration step and 20 Hz telemetry export. It begins with a two-second stabilization interval, engages heading/altitude/airspeed hold, commands a 30° heading change, a 120 m altitude change, a 5 m/s airspeed change, then applies and clears a 12 m/s crosswind. The run records true state, setpoints, controller errors, command/actuator values, saturation flags, events, and termination reason.

Metrics are computed from named windows and emitted beside each CSV as a JSON summary. See [the assumptions](docs/assumptions-and-limitations.md), [architecture](docs/architecture.md), and [requirements-to-test map](docs/requirements-to-test.md) before interpreting results.


## Evidence and limitations

The test suite includes angle wrapping, PID saturation, deterministic same-toolchain replay, invalid time-step rejection, and a real JSBSim load/trim/advance smoke test. It does not establish cross-platform bitwise replay, model validation, controller robustness over a full envelope, sensor realism, or flight safety.
